# Advanced AI verification

Use these exercises to distinguish three kinds of evidence: predictions at sampled inputs, concrete counterexamples, and formal guarantees over a specified input region. Open the training MATLAB Project and run each Live Script section in order.

Required products: MATLAB R2026b, Deep Learning Toolbox, and AI Verification Library for Deep Learning Toolbox. The examples run on a CPU with supplied or synthetic data.

## Trained SOC network: bounds and input-distribution shifts

The SOC exercise trains a regression network from battery measurements generated by the teaching model. Its `softplusLayer` is supported by formal verification in R2026b. The layer itself was available earlier; its verification support is the new capability.

Use acquisition runs 1 to 7 for training and run 8 for choosing model and verification settings. Reserve runs 9 and 10 for final evaluation after those choices are frozen.

The local property is: for a fixed reference SOC and a declared voltage/current/temperature uncertainty box, every network prediction shall remain within **0.03 absolute SOC** of the reference. This is a pointwise error limit over a region, rather than an aggregate RMSE limit.

1. Train the network and inspect validation error.
2. Choose an operating point and explicit sensor-uncertainty bounds.
3. Call `estimateNetworkOutputBounds` and compare the entire output interval with the allowed error band.
4. Evaluate the eight input-box corners as additional sampled checks.
5. Compare nominal and shifted data using an HBOS distribution discriminator.

An output interval entirely inside the allowed band certifies the property for that box. A conservative bound extending beyond the band does not by itself establish a violating input. A tested input outside the limit is a concrete counterexample; absence of a sampled failure is not a universal proof.

For stronger bounds, enable the optional five-epoch optimizer:

```matlab
boundOptions = alphaCROWNOptions(MaxEpochs=5,ExecutionEnvironment="cpu");
[lower,upper] = estimateNetworkOutputBounds(net,inputLower,inputUpper, ...
    Algorithm=boundOptions);
```

`alphaCROWNOptions` is available from R2026a. Compare the resulting bound and elapsed time rather than assume it always improves a particular case.

The regression OOD detector uses the **HBOS** method and intermediate network activations. Ordinary numeric matrices with `InputDataFormats="BC"`, explicit batch size, and CPU execution exercise R2026b input-handling improvements. Report the fractions of nominal observations flagged ID and shifted observations flagged OOD. These are calibrated distribution decisions, not formal safety certificates.

The exercise saves the trained model, input box, bounds and distribution observations in `generated/verification/trainedSOCVerification.mat`. Recheck properties when the model changes.

## Digit classifier: adversarial search and formal robustness

Train a small CNN with `trainnet` and cross-entropy using up to 1600 shipped training images for six epochs. Evaluate separate test images and select correctly classified inputs before searching for an attack.

The student starting point uses a pixel budget of **0.05** and one FGSM attempt. The solution uses **0.1** and at most two attempts: FGSM, followed by ten-step BIM only when needed. Bounds are clipped to the valid pixel range [0,1]. A pixel budget is a numerical constraint; inspect the images before describing a change as imperceptible.

`findAdversarialExamples` returns examples, their predicted labels, and `iX`, which identifies their original inputs. If search finds nothing, record **noneFound** and retain the finite search budget. This outcome does not prove robustness.

`verifyNetworkRobustness` returns:

| Formal result | Interpretation |
|---|---|
| `verified` | The class is invariant throughout the specified box |
| `violated` | The class-invariance property does not hold |
| `unproven` | This verifier did not decide the property |

Keep the solver result separate from the **overall verdict**. A validated counterexample for the same first image, inside its exact bounds and with a changed predicted class, proves violation even if the solver reports `unproven`. A counterexample for another image does not determine the first image's verdict.

The exercise saves its network and observed evidence in `generated/verification/digitVerification.mat`. These properties apply to their stated regions; they do not establish a complete deployed system's safety.
