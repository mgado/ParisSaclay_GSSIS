# Recovery during the live workshop

- **Project closed:** reopen the `.prj`; do not repair paths with `addpath`.
- **Missing optional product:** read the API walkthrough, record unavailable,
  and continue to the next independently runnable exercise.
- **Training too slow:** use the compact 12-unit reference and CPU; do not
  replace an executed metric with an invented one.
- **Python/torch unavailable:** run the MATLAB scalar baseline; keep import
  and direct code generation as a documented separate activity.
- **App unavailable:** use the captured screenshot where provided and the
  command-line lesson; label the app activity as a walkthrough.
- **Formal verification unavailable:** check the affine bound analytically;
  that calculation does not substitute for an unexecuted verification API.
- **Hardware unavailable:** run the host model/MEX, then work through the
  target preflight. Do not label it PIL/HIL.
- **Full-field external app absent:** use the small POD field lesson. The
  external app identity/version is still to be supplied by the instructor.

Every failure should retain its message and prerequisite status. Do not hide
failures by calling them passes or deleting the result.
